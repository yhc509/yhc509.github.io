## v2.1.299: compaction while you're away

```cards
logo: anthropic
cards:
  - icon: message-square
    label: 200K+ token chat
  - icon: timer
    label: About 54 min idle
  - icon: minimize-2
    label: Auto compact
  - icon: database
    label: Before 1h cache expiry
```

In the terminal, Claude Code compacts a conversation over 200K tokens once it sits idle for about 54 minutes, before its one-hour prompt cache expires. Your next message then doesn't reprocess the whole thing. CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS changes the 200K minimum. "idleCompaction": false in settings.json turns it off. Both need v2.1.290 or later. Anthropic hasn't said whether it also runs outside the terminal, in VS Code or the desktop app.

### Source

[Claude Code GitHub release, Oct 14](https://github.com/anthropics/claude-code/releases/tag/v2.1.299)

### My take

Long conversations getting compacted is natural. What matters is whether it happens when you want it to. I always compact manually. The right moments are when one task is done, when one category of a long task is done, or before I step away for a long time. A cache miss with a nearly full context is a waste.

## Compared with when I compact by hand

```matrix

  - icon: check-check
    label: One task done
    cells: [check, none]
  - icon: layers
    label: One category of a long task done
    cells: [check, none]
  - icon: coffee
    label: Stepping away for long
    cells: [check, check]

  check: Covered
  none: Not covered
```

Idle compaction runs when a conversation has 200K tokens or more and has sat idle for about 54 minutes. It doesn't check whether a task or category is finished. So of the three moments, it only covers stepping away. Anthropic hasn't said whether you can choose what the summary keeps.

## v2.1.300: more tracing, resume fixes

```cards
logo: anthropic
cards:
  - icon: activity
    label: More OTel tracing
  - icon: database
    label: Cache writes split 5m / 1h
  - icon: history
    label: Resume history fix
```

- The OpenTelemetry api_request event now has cache_creation_5m_tokens and cache_creation_1h_tokens. You can split cache writes by lifetime.
- Trace spans get OpenTelemetry GenAI semantic-convention attributes such as gen_ai.provider.name, gen_ai.conversation.id, gen_ai.tool.name and error.type.
- Anthropic fixed lost recent messages when resuming a headless or Agent SDK session. The bug hit when a compaction followed a reply cut at the output token limit. The messages that compaction kept then disappeared. The fix applies to compactions from this version on.
- When a compaction followed a retried or unfinished reply in the same turn, resuming could lose the compaction summary or bring back pre-compaction history. That is fixed too.
- If a crash had cut a transcript's last line short, resuming used to lose the first entry written afterward. Anthropic fixed that as well.
