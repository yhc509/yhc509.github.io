## Codex 28일 챌린지 22일차, CLI 0.164.0에 /presets 추가

```cards
logo: openai
cards:
  - icon: bookmark
    label: 프롬프트 프리셋
  - icon: terminal
    label: 모델, 권한 인라인 인자
  - icon: image
    label: 이미지 미리보기
  - icon: plug
    label: 엔터프라이즈 MCP 로그인
caption: Codex CLI 0.164.0
```

tibo가 10월 5일 05:33 KST에 28일 챌린지를 시작했다. 매일 Codex와 Work 사용자 대부분에게 도움이 되는 개선을 하나 내놓거나, 사용량을 전부 초기화하겠다는 약속이다. 22일차 글은 10월 27일 04:24 KST에 올라왔고 "Day 22/ Terra is back!"이 내용의 전부다. Codex CLI 0.164.0은 10월 23일 13:48 KST에 나왔다.

- 19일차 글은 10월 24일 08:12 KST에 올라왔다. dots의 통화 연결이 빨라졌고, 대화 도중 추론 강도를 바꿔도 캐시가 무효화되지 않는다고 했다.
- 이어진 글에서 tibo는 CLI 사용량이 devday 이후 2배가 됐다고 적었다.
- /presets는 반복하는 프롬프트와 슬래시 명령을 번호 칸 10개에 저장하고 Ctrl+X P 메뉴로 부른다. /model과 /permissions는 모델, 추론 강도, 속도, 권한 프로필을 인자로 받는다. 전체 화면 기록은 Kitty와 Sixel 터미널에서 이미지를 미리 보여 준다.
- 엔터프라이즈 MCP 로그인은 Codex 계정 권한이나 전용 로그인으로 들어가고, 비밀 값이 필요한 OAuth 클라이언트도 지원한다. 원격 Bash와 Zsh 스냅샷 세션은 자격 증명을 가리고, Amazon Bedrock 설정 마법사는 기본으로 켜졌다.
- 압축에 실패해도 요약이 반쯤 남지 않고, 압축된 기록도 이어 열리며 스레드 설정이 돌아온다. Windows에서는 Negotiate와 NTLM으로 HTTPS, WebSocket 프록시 인증을 한다. 하위 명령으로 내려가도 -c 설정 덮어쓰기가 유지되고, 대기 중인 프롬프트는 권한 선택이 끝날 때까지 기다린다. macOS 샌드박스도 강화했다.
- Codex CLI를 만드는 Felipe Coury(X @fcoury)는 코드 리뷰와 수정을 오가는 작업에서 프리셋을 Ctrl+X P로 불러 쓰는 영상을 올렸다. 독립적인 사용 후기는 찾지 못했다.
- 0.164.0이라는 버전 번호는 tibo의 19일차 글에 없다. 같은 기능을 정리한 릴리스 노트와 나온 시각이 맞아서 같은 업데이트로 보았다.

## Cursor 데스크톱 앱에 Computer Use, CLI v2026.10.22

```cards

  - icon: at-sign

  - icon: terminal

```

Cursor가 10월 24일 00:59 KST에 공식 X로 Computer Use를 공개했다. 에이전트가 클릭과 입력으로 컴퓨터의 앱을 직접 다루고, 작업에 필요하면 Cursor가 알아서 쓴다. 업데이트하면 바로 써 볼 수 있다.

- Windows 앱에서도 돌아간다. 10월 24일 Cursor 포럼에 Windows 앱의 Computer Use 권한 문제를 보고한 글이 올라왔다.
- 셀프 호스트 워커는 agent worker --computer-use start로 직접 켜야 한다. macOS에서는 "Cursor Computer Use"라는 보조 앱에 손쉬운 사용과 화면 기록 권한을 줘야 한다.
- CLI v2026.10.22는 agent env deploy --env <id>로 기존 Cloud Agent 환경을 갱신한다. 셀프 호스트 워커는 agent login이나 agent team switch로 고른 팀에 등록된다.
- 막혀 있거나 Max 전용이거나 쓸 수 없는 모델에 고정한 커스텀 서브에이전트는 부모 모델로 돌고, 어느 모델로 돌았는지 알려 준다. Composer 2.5 서브에이전트는 빠른 등급이 아니라 표준 속도로 돌고 표준 속도로 과금된다.
- 하위 폴더의 파일을 고치거나 만들 때 그 폴더의 AGENTS.md와 항상 적용 규칙이 붙는다. 컴파일 캐시와 지연 초기화로 따뜻한 상태의 부팅 시간이 약 10% 줄었다.
- X @qi9098은 Cursor 공식 예제 앱에 즐겨찾기 기능을 넣고 iOS 시뮬레이터에서 눌러 보게 했다. 같은 프롬프트로 Codex gpt-6-astra high는 2분 1초, Codex gpt-6.1-sol high는 2분 8초, Cursor Grok 4.7 High는 8분 17초가 걸렸고, Cursor는 목록 위의 All과 Favorites 전환 버튼에서 3분 넘게 막혔다.
- 데스크톱 앱 출시를 따로 설명한 Cursor 블로그 글이나 변경 내역은 찾지 못했다.

OpenAI가 10월 27일 03시 무렵(KST) GPT-6.1 Terra를 공개했다. ChatGPT Work와 Codex에서 Plus, Pro, Enterprise, Edu 요금제로 쓰고, GitHub Copilot에는 04:15 KST에 정식 출시했다. 최대 추론 강도에서 Terminal-Bench 4.0은 Sol보다 낮고 Agents' Last Exam은 Sol보다 높다.

- Terminal-Bench 4.0에서 Terra는 Low 24.8, Medium 35.8, High 41.8, Xhigh 46.4, Max 50.3이고 Sol은 47.1, 52.7, 53.0, 53.4, 55.9다. Terra는 어느 추론 강도에서도 같은 강도의 Sol보다 낮고, Terra xhigh의 46.4는 Sol low의 47.1에도 못 미친다.
- OpenAI의 모델 선택 안내는 Terra를 "일상적인 글쓰기와 시각 작업", Astra를 "가장 어려운 처음부터 끝까지의 작업", Sol을 "반복되고 오래 걸리는 작업"에 맞는다고 적었다. 가장 복잡한 코딩 작업에는 GPT-6.1 Sol과 GPT-6 Astra가 더 낫다고 밝혔다.
- API 모델명은 gpt-6.1-terra다. 컨텍스트는 1,050,000 토큰이고, 입력은 최대 922,000 토큰, 출력은 최대 128,000 토큰이다. Copilot에서는 Versatile 등급이고, GitHub는 "일상적인 에이전트 코딩과 터미널 작업"용이라고 소개한다.
- tibo는 22일차 글에서 쓰기, 성격, 요청의 뉘앙스를 이해하는 능력이 크게 좋아졌고 컴퓨터 사용이 매우 뛰어나며 API와 구독 모두에서 Sol보다 사용량을 2배 준다고 소개했다. 사용량 2배는 OpenAI 발표 글에서 확인하지 못했다.
- Artificial Analysis는 지능 지수에서 Terra에 48.11점, Sol에 51.83점, Astra에 52.67점을 매겼다. 지수를 돌리는 동안 출력 토큰은 Terra가 128,152,739개, Sol이 67,198,855개로 Terra가 약 1.9배 많았다. Coding Agent Index v2.0은 Terra 48, Sol 54, Luna 31이다.
- AA-Omniscience 환각률은 낮을수록 좋다. Terra는 38.04%로 Sol의 54.27%, Astra의 51.34%보다 낮고 이전 세대 GPT-5.6 Terra의 87.88%에서 내려왔다. 비교한 모델 가운데 Terra보다 낮은 쪽은 Gemini 4 Argon 15.07%와 Grok 4.7 29.34%뿐이다.
- Sol 밑에 붙이는 서브에이전트로 쓴다는 평이 있다. X @adidoit은 한 시간 써 보니 할당량을 거의 쓰지 않았고 컴퓨터 사용이 더 좋아졌다고 했다.
- 컴퓨터 사용이 빠르다. X @victornunez가 같은 긴 양식을 Fast 모드로 채우게 했더니 Terra는 53.5초, Sol은 3분 21.7초가 걸렸다.
- X @taylorhbuilds는 자기 코드로 Codex를 150번 돌려 비교했다. 중앙값은 Terra High가 29초, Sol Medium이 87초였고 50번 중 승인된 결과는 Sol이 9번 더 많았다. 빠른 일에는 Terra, 틀리면 안 되는 일에는 Sol을 쓰고 "Terra를 어디에 쓸지는 아직 모르겠다"고 했다.
- Reddit r/codex의 Plus 사용자는 같은 프로젝트에서 Terra max가 18분에 5시간 한도의 33%를, Sol medium이 약 30분에 24%를 썼다고 했다. 사용량 2배라는 설명과 어긋나는 한 사람의 시험이다.
- r/codex에는 요청한 일을 일찍 끝내고 지적하면 안 했다고 인정한다는 글과, Luna와 Sol을 섞어 쓰면 Terra가 왜 필요한지 모르겠다는 어정쩡한 중간 모델 평가도 올라왔다.
- HN에서 OpenAI 직원 tedsanders는 Terra를 컴퓨터 사용이 빠르고 기술 문서 작성에 강할 수 있는 중간급 API 선택지라고 설명했고, Sol과 Astra를 모두 대체하는 모델은 아니라고 했다.

Moonshot이 10월 23일(미국 날짜) Kimi K3.1 Pro와 Highspeed를 열었다. 컨텍스트는 1M 토큰이고 Kimi Enterprise는 관리자가 켜야 쓸 수 있다. Moonshot 표에서 Terminal-Bench 4.0은 65.7로 Claude Opus 5.5의 66.4보다 0.7점 낮다.

- Moonshot은 K3.1 Pro가 K3의 추가 학습판이고 추가 학습 연산량이 훨씬 늘었다고 설명한다. Kimi.ai, Kimi 모바일 앱, Kimi Work, Kimi Code, Kimi API에서 쓰고 입력은 텍스트와 이미지다.
- 크기는 Moonshot이 3T급이라 하고 Artificial Analysis는 전체 2.8T에 활성 104B로 적는다.
- 가중치는 2026년 11월 4일까지 풀겠다는 약속이다. 2026년 10월 27일 현재는 공개 전이다.
- Highspeed는 공식으로 2~3배 빠르다. AIHubMix가 직접 재 보니 1.6~1.75배였고 토큰의 85~90%가 추론 토큰이었다.
- Artificial Analysis 지능 지수는 55로 4위이고 GDPval-AA는 1,846 Elo로 3위다. 직접 잰 Terminal-Bench 4.0은 67%로 측정한 모델 중 가장 높고 Claude Sonnet 5.5는 64%, K3는 13%다. Moonshot의 65.7과는 잰 곳이 달라서 하네스와 조건이 같은지 알 수 없다.
- AA-Omniscience 환각률은 K3의 53.20%에서 43.89%로 내려갔고 AutomationBench-AA는 58%에서 73%로 올랐다. Moonshot 내부 Hallu Bench Hard의 주장 단위 환각률은 K3의 23.4%에서 K3.1의 8.3%로 내려갔다.
- Hacker News 스레드는 10월 24일 01:59 KST에 올라왔고 1,089점, 댓글 655개를 받았다. 오픈 웨이트에서 사이버 관련 데이터를 뺐고 그 역량을 의도적으로 제한했다는 댓글이 나왔고(TuxSH, rudolftheone), Terminal-Bench 4는 포화에 가깝다는 지적도 있었다(Tiberium).
- simonw는 Moonshot의 크리에이터 캠페인 문서를 보면 유료 홍보 계정을 가려낼 수 있다고 했고, taytus는 사용량 한도 불만을 올렸다.
- X @ValgoDev는 같은 three.js 등대 프롬프트를 세 에이전트에 줬다. Kimi는 5.6분, Codex는 8.8분, Claude Code는 17.3분이 걸렸고 Claude의 결과가 가장 낫고 Kimi는 화면이 너무 어두웠다고 했다.
- X @PovilasKorop은 K3.1 Pro를 MAX 수준으로 돌려 High보다 점수는 높았지만 속도는 2.5배 느렸다고 했다. Kimi 서버가 가득 차서 429 오류를 몇 번 만났다.
