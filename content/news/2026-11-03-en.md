Versions 2.1.312 and 2.1.313 of the Claude Code extension on Cursor's marketplace were tampered copies that Anthropic did not build. Cursor put the exposure window at 18:27 KST on October 29 (09:27 UTC) through 05:35 KST on October 30 (20:35 UTC on October 29). The impact is at most 5,000 users.

- The attacker reused the version number of the real 2.1.312. Anthropic shipped that build at 05:24 KST on October 28 (20:24 UTC on October 27). The 2.1.312 and 2.1.313 files on the marketplace are copies Anthropic did not build. That version number alone does not separate the real build from the tampered one. Cursor named these two versions for Windows and macOS as malicious.
- Cursor put the exposure window at 18:27 KST on October 29 (09:27 UTC) through 05:35 KST on October 30 (20:35 UTC on October 29). The ceiling is 5,000 users. The X post went out at 16:46 KST on October 30 (07:46 UTC). The blog update at 03:30 KST on October 31 (18:30 UTC on October 30) added IOCs. That update marked 2.1.312 malicious. Anthropic shipped the clean 2.1.314 at 10:06 KST on October 30 (01:06 UTC).
- Phorion wrote that the malicious code runs as an IIFE as soon as the extension file loads. The code adds an SSH key. It opens a reverse tunnel. It sets persistence. It collects environment variable names. On the four Macs Expel investigated, hostname, username, OS, home directory, working directory, Git email, public IP, and environment variable names left the machine. The tunnel connected for a user who was not an admin. Expel did not see a successful attacker SSH login.
- The tampered copies were not on the VS Code Marketplace, Open VSX, or npm. Anthropic engineer ddworken wrote that the official channels, including VS Code and Open VSX, are not affected. Microsoft Threat Intelligence confirmed that the VS Code Marketplace and npm were not affected. Phorion first named Open VSX. It corrected the affected marketplace to Cursor at 18:13 KST on October 30 (09:13 UTC).
- Felix Rieseberg said this was not a compromise of Anthropic's systems or employee laptops. He said a malicious actor used access to Cursor's marketplace to publish a tampered copy. He said this only impacts Cursor users.
- Expel investigated four Macs. One of them first ran at 13:45 KST on October 30 (04:45 UTC), about 8 hours after the window closed, when the user logged in. Expel wrote that looking only at that window can miss infected machines. It saw no evidence that the marketplace kept serving the tampered copy after the window.
- The latest Cursor notice says to check with its commands and the IOC list. It also says to check `~/.ssh/authorized_keys` and persistence. Removing the extension alone is not enough. Run the cleanup script. Update to 2.1.314 or later. Rotate credentials if a machine was affected.

https://x.com/cursor_ai/status/2116074289053175808

https://x.com/felixrieseberg/status/2116170451466543578

- Extension auto-update runs with the logged-in user's permissions. Phorion wrote that a backdoored extension gets the permissions of the IDE and of the user running it.
- On Hacker News (1,007 points, 553 comments) the top themes were signing, auto-update delay, and whose key was used to publish. Cursor and Anthropic have not said how the attacker got publish access. They have not said how many real intrusions there were.

### My take

I use Claude Code only as the terminal CLI. I do not run it as the Cursor extension. This tampered copy did not reach me. Extension auto-update settings stay as they are.
