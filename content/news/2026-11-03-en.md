Versions 2.1.312 and 2.1.313 of the Claude Code extension on Cursor's marketplace were tampered copies that Anthropic did not build. Cursor's exposure window runs from 18:27 KST on October 29 (09:27 UTC) to 05:35 KST on October 30 (20:35 UTC on October 29). Cursor says the impact is at most 5,000 users.

- The attacker reused the version number of the real 2.1.312, which Anthropic shipped at 05:24 KST on October 28 (20:24 UTC on October 27). The 2.1.312 and 2.1.313 files on Cursor's marketplace are copies Anthropic did not build. The version number 2.1.312 alone does not separate the real build from the tampered one. Cursor named these two versions for Windows and macOS as malicious.
- Cursor's exposure window runs from 18:27 KST on October 29 (09:27 UTC) to 05:35 KST on October 30 (20:35 UTC on October 29). Cursor put the ceiling at 5,000 users. Cursor announced it on X at 16:46 KST on October 30 (07:46 UTC). Cursor updated the blog at 03:30 KST on October 31 (18:30 UTC on October 30), added IOCs, and marked 2.1.312 malicious. Anthropic shipped the clean 2.1.314 at 10:06 KST on October 30 (01:06 UTC).
- Phorion wrote that the malicious code runs as an IIFE as soon as the extension file loads. The code adds an SSH key. The code opens a reverse tunnel. The code sets persistence. The code collects environment variable names. On the four Macs Expel investigated, the collection included hostname, username, OS, home directory, working directory, Git email, public IP, and environment variable names. Expel saw the tunnel connect for a user who was not an admin. Expel did not see a successful attacker SSH login.
- The tampered copies were not on the VS Code Marketplace, Open VSX, or npm. David Dworken of Anthropic wrote that the official channels, including VS Code and Open VSX, are not affected. Microsoft Threat Intelligence confirmed that the VS Code Marketplace and npm were not affected. Phorion first named Open VSX, then corrected the affected marketplace to Cursor at 18:13 KST on October 30 (09:13 UTC).
- Felix Rieseberg said this was not a compromise of Anthropic's systems or employee laptops. Felix Rieseberg said a malicious actor used access to Cursor's marketplace to publish a tampered copy. Felix Rieseberg said this only impacts Cursor users.
- Expel investigated four Mac cases. In one case the code first ran at 13:45 KST on October 30 (04:45 UTC), about 8 hours after the window closed, when the user logged in. Expel wrote that some organizations may be scoping too narrowly if they look only at that window. Expel saw no evidence that the marketplace kept serving the tampered copy after the window.
- Cursor says to run the check commands and the IOC list in the latest notice. Cursor says to check `~/.ssh/authorized_keys` and persistence. Cursor says removing the extension alone is not enough, and to run Cursor's cleanup script. Cursor asks customers to update to 2.1.314 or later. Cursor says to rotate credentials if a machine was affected.

https://x.com/cursor_ai/status/2116074289053175808

https://x.com/felixrieseberg/status/2116170451466543578

- Extension auto-update runs with the logged-in user's permissions. Phorion wrote that a backdoored extension gets the permissions of the IDE and of the user running it.
- On Hacker News (1,007 points, 553 comments) the top themes were signing, auto-update delay, and whose key was used to publish. Cursor and Anthropic have not said how the attacker got publish access. The two companies have not said how many real intrusions there were.

### My take

I use Claude Code only as the terminal CLI. I do not run it as the Cursor extension, so this tampered copy did not reach me. I will leave my extension auto-update settings as they are. I already went through a supply-chain incident with LiteLLM, and I wrote that up in [this post](/posts/agentic/litellm-supply-chain-attack).
