Versions 2.1.312 and 2.1.313 of the Claude Code extension on Cursor's marketplace were tampered copies that Anthropic did not build. Cursor put the exposure window at 18:27 KST on October 29 (09:27 UTC) through 05:35 KST on October 30 (20:35 UTC on October 29). The impact is at most 5000 users.

- The attacker reused the version number of the real 2.1.312. The 2.1.312 and 2.1.313 files on the marketplace are copies Anthropic did not build. That version number alone does not separate the real build from the tampered one. Cursor named these two versions for Windows and macOS as malicious.
- Cursor serves extensions from marketplace.cursorapi.com, not straight from Open VSX. Socket found no publication or removal event for 2.1.313. Ars and The Register reported that neither company explained the entry point.
- Phorion wrote that the malicious code runs as an IIFE as soon as the extension file loads. The code adds an SSH key. It opens a reverse tunnel. It sets persistence. It collects environment variable names. On the four Macs Expel investigated, hostname, username, OS, home directory, working directory, Git email, public IP, and environment variable names left the machine. The tunnel connected for a user who was not an admin. Expel did not see a successful attacker SSH login. Extension auto-update runs with the logged-in user's permissions. Phorion wrote that a backdoored extension gets the permissions of the IDE and of the user running it.
- The tampered copies were not on the VS Code Marketplace, Open VSX, or npm. Anthropic engineer ddworken wrote that the official channels, including VS Code and Open VSX, are not affected. Microsoft Threat Intelligence confirmed that the VS Code Marketplace and npm were not affected.
- Expel investigated four Macs. It wrote that looking only at the exposure window can miss infected machines. It saw no evidence the marketplace kept serving the tampered copy afterward.
- The latest Cursor notice says to check with its commands and the IOC list. It also says to check `~/.ssh/authorized_keys` and persistence. Removing the extension alone is not enough. Run the cleanup script. Update to 2.1.314 or later. Rotate credentials if a machine was affected.
- On Hacker News (1,007 points, 553 comments) the top themes were signing, auto-update delay, and whose key was used to publish. Cursor and Anthropic have not said how many real intrusions there were.
