## Vercel이란?

Vercel은 Next.js를 만든 회사에서 운영하는 클라우드 플랫폼입니다. 프론트엔드 프로젝트, 특히 Next.js 애플리케이션을 배포하는 데 최적화되어 있습니다.

### Vercel의 주요 특징

- **Zero Configuration**: 별도 설정 없이 Git 저장소 연결만으로 배포
- **자동 HTTPS**: SSL 인증서 자동 발급 및 갱신
- **글로벌 CDN**: 전 세계 Edge 네트워크를 통한 빠른 콘텐츠 전송
- **Preview Deployments**: PR마다 자동으로 미리보기 환경 생성
- **Serverless Functions**: API 라우트 자동 서버리스 함수 변환

### Vercel vs 다른 호스팅 서비스

| 특징 | Vercel | Netlify | GitHub Pages |
|------|--------|---------|--------------|
| Next.js 지원 | 최적화 | 제한적 | 정적만 |
| 서버리스 함수 | ✅ | ✅ | ❌ |
| ISR 지원 | ✅ | ❌ | ❌ |
| 무료 플랜 | 개인 무제한 | 월 300분 빌드 | 무제한 |

> **ISR (Incremental Static Regeneration)** 이란?
> 빌드 후에도 특정 페이지만 선택적으로 재생성할 수 있는 Next.js의 기능입니다. Vercel은 이를 완벽하게 지원합니다.

## 1단계: 사전 준비

### GitHub 저장소 준비

먼저 프로젝트를 GitHub에 푸시해야 합니다.

```bash
# Git 초기화 (이미 되어있다면 생략)
git init

# 모든 파일 스테이징
git add .

# 커밋
git commit -m "Initial commit"

# GitHub 저장소 연결 (본인의 저장소 URL로 변경)
git remote add origin https://github.com/username/my-blog.git

# 푸시
git push -u origin main
```

### .gitignore 확인

배포 전 `.gitignore` 파일에 다음 항목들이 포함되어 있는지 확인하세요:

```gitignore
# 의존성
node_modules/

# 빌드 결과물
.next/
out/

# 환경 변수 (민감 정보)
.env
.env.local
.env.production.local

# 디버그 로그
npm-debug.log*

# IDE 설정
.idea/
.vscode/

# OS 파일
.DS_Store
```

> **왜 node_modules를 제외할까요?**
> `node_modules`는 `package.json`을 기반으로 언제든 재생성할 수 있습니다. 용량이 크고 OS별로 다를 수 있어 Git에 포함하지 않습니다. Vercel은 빌드 시 자동으로 `npm install`을 실행합니다.

## 2단계: Vercel 계정 생성 및 프로젝트 연결

### 2.1 Vercel 가입

1. [vercel.com](https://vercel.com)에 접속
2. **Sign Up** 클릭
3. **Continue with GitHub** 선택 (권장)

GitHub 계정으로 로그인하면 저장소 접근 권한을 쉽게 설정할 수 있습니다.

### 2.2 새 프로젝트 생성

1. 대시보드에서 **Add New → Project** 클릭
2. **Import Git Repository** 섹션에서 저장소 선택
3. 저장소가 보이지 않으면 **Adjust GitHub App Permissions** 클릭하여 권한 추가

### 2.3 프로젝트 설정

Import 화면에서 다음 설정을 확인합니다:

```
Project Name: my-blog (URL에 사용됨)
Framework Preset: Next.js (자동 감지)
Root Directory: ./ (모노레포가 아니면 기본값)
```

#### Build & Output Settings

대부분의 경우 기본값으로 충분합니다:

| 설정 | 기본값 | 설명 |
|------|--------|------|
| Build Command | `next build` | 빌드 명령어 |
| Output Directory | `.next` | 빌드 결과물 위치 |
| Install Command | `npm install` | 의존성 설치 명령어 |

> **Framework Preset의 역할**
> Vercel은 프레임워크를 자동 감지하여 최적의 빌드/배포 설정을 적용합니다. Next.js의 경우 서버 컴포넌트, API Routes, 미들웨어 등을 자동으로 서버리스 함수로 변환합니다.

## 3단계: 환경 변수 설정

### 환경 변수가 필요한 경우

프로젝트에서 API 키나 시크릿을 사용한다면 환경 변수를 설정해야 합니다.

```typescript
// 예: src/app/layout.tsx
const BASE_URL = process.env.NEXT_PUBLIC_BASE_URL || "https://example.com";
```

### Vercel에서 환경 변수 추가

1. Project Settings → Environment Variables 이동
2. 변수 추가:

```
Name: NEXT_PUBLIC_BASE_URL
Value: https://my-blog.vercel.app
```

3. 환경 선택:
   - **Production**: 실제 배포 환경
   - **Preview**: PR 미리보기 환경
   - **Development**: 로컬 개발 시 (vercel dev)

### NEXT_PUBLIC_ 접두사의 의미

```typescript
// 서버에서만 사용 (노출 안됨)
process.env.DATABASE_URL

// 클라이언트에서도 사용 (브라우저에 노출됨)
process.env.NEXT_PUBLIC_BASE_URL
```

> **보안 주의사항**
> `NEXT_PUBLIC_` 접두사가 붙은 변수는 클라이언트 번들에 포함되어 브라우저에서 볼 수 있습니다. API 키나 비밀번호는 절대 이 접두사를 사용하지 마세요.

## 4단계: 배포 실행

### 첫 배포

**Deploy** 버튼을 클릭하면 배포가 시작됩니다.

배포 과정:
```
1. Cloning repository...
2. Installing dependencies...
3. Running build command...
4. Deploying to edge network...
5. ✅ Deployment complete!
```

### 빌드 로그 확인

빌드 중 문제가 발생하면 로그를 확인하세요:

```bash
# 성공적인 빌드 예시
info  - Creating an optimized production build
info  - Compiled successfully
info  - Collecting page data
info  - Generating static pages (10/10)
info  - Finalizing page optimization

Route (app)
┌ ○ /
├ ○ /about
├ ● /posts/[slug]
└ ○ /projects
```

### 배포 URL 구조

배포가 완료되면 여러 URL이 생성됩니다:

```
# 프로덕션 URL (main 브랜치)
https://my-blog.vercel.app

# 고유 배포 URL (모든 배포마다 생성)
https://my-blog-abc123xyz.vercel.app

# 브랜치 URL
https://my-blog-git-feature-branch.vercel.app
```

## 5단계: 자동 배포 설정

### Git 연동 배포

Vercel은 기본적으로 Git 푸시 시 자동 배포됩니다:

| 이벤트 | 결과 |
|--------|------|
| `main` 브랜치에 푸시 | 프로덕션 배포 |
| 다른 브랜치에 푸시 | Preview 배포 |
| PR 생성 | Preview 배포 + 댓글에 URL |

### 배포 워크플로우

```
feature 브랜치 작업
        ↓
    PR 생성
        ↓
Preview 배포 (자동) → 테스트 및 리뷰
        ↓
    main에 머지
        ↓
프로덕션 배포 (자동)
```

### 특정 브랜치만 배포하기

Settings → Git에서 Production Branch를 변경할 수 있습니다:

```
Production Branch: main
Ignored Build Step: 특정 조건에서 빌드 스킵
```

## 6단계: 커스텀 도메인 연결

### 도메인 추가

1. Settings → Domains 이동
2. 도메인 입력: `myblog.com`
3. **Add** 클릭

### DNS 설정

Vercel이 안내하는 DNS 레코드를 도메인 등록 업체에서 설정합니다:

```
# A 레코드 (루트 도메인)
Type: A
Name: @
Value: 76.76.21.21

# CNAME 레코드 (www 서브도메인)
Type: CNAME
Name: www
Value: cname.vercel-dns.com
```

### SSL 인증서

도메인 연결 후 Vercel이 자동으로 Let's Encrypt SSL 인증서를 발급합니다. 보통 몇 분 내에 완료됩니다.

> **DNS 전파 시간**
> DNS 변경은 전 세계에 전파되는 데 최대 48시간이 걸릴 수 있습니다. 대부분 1-2시간 내에 완료됩니다.

```tsx
      </body>
```

```bash
npm install @vercel/speed-insights
```

```tsx
import { SpeedInsights } from '@vercel/speed-insights/next';

// layout.tsx에 추가
```

## 문제 해결

### 빌드 실패 시

```bash
# 로컬에서 먼저 빌드 테스트
npm run build

# 타입 에러 확인
npx tsc --noEmit

# 린트 에러 확인
npm run lint
```

### 일반적인 에러들

**1. Module not found**
```
의존성이 package.json에 있는지 확인
npm install 재실행
```

**2. Environment variable is undefined**
```
Vercel 대시보드에서 환경 변수 설정 확인
NEXT_PUBLIC_ 접두사 확인 (클라이언트용)
```

**3. 404 에러**
```
동적 라우트의 generateStaticParams 확인
output: 'export' 설정 시 동적 기능 제한
```

### 빌드 캐시 초기화

문제가 지속되면 캐시를 초기화해보세요:

1. Settings → General
2. **Build Cache** 섹션
3. **Clear Cache** 클릭

## CLI로 배포하기

GUI 대신 CLI를 선호한다면:

```bash
# Vercel CLI 설치
npm i -g vercel

# 로그인
vercel login

# 프로젝트 디렉토리에서 배포
vercel

# 프로덕션 배포
vercel --prod

# 환경 변수와 함께 배포
vercel --env DATABASE_URL=xxx --prod
```

### 유용한 CLI 명령어

```bash
# 프로젝트 연결
vercel link

# 환경 변수 가져오기 (.env.local 생성)
vercel env pull

# 로컬에서 Vercel 환경으로 개발
vercel dev

# 배포 목록 확인
vercel ls

# 특정 배포 삭제
vercel rm [deployment-url]
```
